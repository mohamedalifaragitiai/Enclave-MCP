Sovereign MCP Platform

A local, fully open-source Model Context Protocol platform: a LangGraph agent acting as MCP host over two independent MCP servers, with every reasoning step served by one already-running local LLM. No cloud API, no second model, no writes to C:\.

01Runtime architecture

Read this first

This diagram documents the system that runs, not the one originally drawn. HLD §2 shows three sibling containers joined by stdio. That topology is not realisable — stdio works by a parent process owning a child's stdin/stdout, and sibling containers share no process tree. Under compose those edges are HTTP. The discrepancy is recorded rather than quietly corrected, because HLD.md is the design baseline.

03Ownership of the MCP primitives

All three primitives are exercised end to end. How responsibility divides between server and host is the part worth defending in review.

PrimitiveOwnerRationale
ToolsServerThe server's JSON Schema passes through untouched into OpenAI function specs. Adding a tool needs no host change.
PromptsServerrag_answer is fetched via prompts/get rather than hardcoded — the server owns how its own corpus should be used.
ResourcesHost bridgesResources are host-controlled and not model-addressable. The host exposes chunk:// as a synthetic read_chunk tool and translates the call back into resources/read.
Design tension

Prompts are server-scoped; orchestration is not. rag_answer ends by telling the model to abstain when search finds nothing relevant — correct while rag_server stands alone, actively wrong once docs_server exists, because not in the index stopped meaning not in the corpus. Cross-server guidance is therefore composed by the host from its live routing table. Neither server knows the other exists.

04Request path

question
  └─ agent merges both servers' tools into one namespace
     ├─ 1  search_documents            → rag_server   (HTTP + x-api-key)
     │       └─ "1 file is NOT in this index: scanned_osha_hotwork.pdf"
     ├─ 2  parse_document              → docs_server  (HTTP + x-api-key)
     │       └─ pdfminer finds 0 chars → Tesseract OCR
     └─ 4  reasoning                   → host.docker.internal:8001
              └─ 5  port proxy         → 127.0.0.1:8001
grounded answer, cited to the source file

Step 1's disclosure is what makes multi-server routing work at all. Without rag_server reporting the files it cannot see, the agent abstained on a question whose answer sat in an un-ingested scanned PDF.

05Security boundaries

  • API key at the transport edge — checked before any MCP handler runs, using hmac.compare_digest so early-mismatch timing leaks nothing.
  • Fails closed — with the key env var unset the server refuses to start and exits non-zero, rather than starting unauthenticated.
  • No published ports — servers are reachable only on the compose network.
  • Path traversal refused — docs_server resolves filenames against the corpus root; ../../../etc/passwd is rejected.
  • Docker socket never mounted — preserving stdio under compose would have required it, which is root-equivalent host access. Rejected in favour of HTTP.
  • Inference stays loopback-bound — a port proxy on the WSL-facing adapter forwards to 127.0.0.1, so the model is never exposed to the LAN and the shared process is never restarted.
What the API key is not

One shared secret, correctly placed and correctly failing closed. There is no per-user identity, no per-tool scoping, no rotation, no audit trail, no transport encryption and no rate limiting. The production successor is an identity provider issuing short-lived scoped tokens. This is the seed of an auth story, not a complete one.

08Known limitations

  • The scanned fixture is synthetic — the real OSHA/EIA PDF corpus is not yet present. Reproducible via scripts/make_scanned_fixture.py.
  • The 0.50 similarity floor is calibrated against three fixtures and needs retuning once the real corpus is ingested.
  • docs_server output is not fed back into ChromaDB — OCR text reaches the agent but does not persist to the index.
  • Tool selection on a 4B model is not deterministic, so the verification scripts drive cross-server dispatch directly rather than relying on the model choosing it.
  • The diagram hardcodes the WSL host address and current image sizes; both drift and should be checked when regenerating.

09Running the stack

wsl -d DockerEngine
cd /mnt/m/MCP_Project

cp .env.example .env                 # then set real keys
docker compose build
docker compose up -d rag_server docs_server
docker compose run --rm agent "What does OSHA require for mechanical integrity?"

Without RAG_SERVER_URL and DOCS_SERVER_URL set, the same agent code runs against servers spawned as local subprocesses over stdio instead — useful for development, and the reasoning loop never learns which transport is in use.
